# 재무 데이터 계약 — 게이트의 나머지 절반

## 1. 발견

승인 보조 리뷰어가 DART발 예외를 다루지 못하는 문제를 고치려다, 더 큰 것이 나왔다.

`check_quality`·`decide_serving`·`ledger.stage` 는 `pipeline.py` 의 **ECOS 루프에만**
있었다. DART 재무는 응답 계약만 통과하고 곧바로 창고로 들어갔다.

```
금리:  응답 계약 -> 스키마 계약 -> 품질 계약 -> 승인 게이트 -> 서빙 판정 -> 적재
재무:  응답 계약 ----------------------------------------------------> 적재
```

노출 규모를 쟀다.

| | |
|---|---|
| 서빙 테이블 총 행 | 50 |
| 재무가 구동한 행 | **50 (전부)** |
| 금리가 붙은 행 | 50 (LEFT JOIN 되는 맥락) |

`serving_insurer_rate_context` 의 `FROM` 절은 `financials` 다. 금리는 `LEFT JOIN` 으로
붙는다. **게이트가 걸려 있던 쪽은 맥락이었고, 제품을 구동하는 쪽은 열려 있었다.**

프로젝트의 한 줄 정의가 "계약을 위반한 금융 데이터가 서빙에 도달하는 것을 차단한다"인데,
그 주장이 데이터의 절반, 그것도 덜 중요한 절반에만 성립하고 있었다.

## 2. 품질 규칙 — 전부 실측에서 유도

| 규칙 | 실측 근거 |
|---|---|
| `BALANCE_SHEET_BROKEN` | 자산 = 부채 + 자본이 50개 회사-분기 전부에서 상대오차 **0.000e+00** |
| `NEGATIVE_STOCK` | 자산·부채·자본·이익잉여금·보험계약부채 음수 **0건** |
| `MISSING_INDICATOR` | 5사 × 10분기에서 총자산·자본·손익 **10/10 존재** |
| `ASSET_JUMP_EXCEEDED` | 총자산 분기 변동 **−2.88% ~ +8.73%**, 평균 절대 2.61%, p95 6.14% |
| `NO_INDICATORS` | 빈 결과를 통과로 넘기면 빈 서빙이 정상이 된다 |

**부호 규칙은 지표마다 다르다.** 손익과 이자비용은 음수가 실제로 존재한다
(net_income 1건, operating_income 2건, interest_expense 4건). 적자 분기이므로 정상이다.
일괄 "음수 금지"를 적용했다면 정상 데이터를 막았을 것이다.

**급변 임계는 관측 최대(+8.73%)보다 위여야 한다.** 25%로 뒀다. 관측 최대의 약 3배이고,
보험사 총자산이 한 분기에 25% 움직이면 확인이 필요한 규모다.

## 3. 더 큰 발견 — 응답 순서가 데이터의 의미를 정하고 있었다

품질 계약을 만든 뒤 실제 보존된 원본으로 오염 주입을 했다. 자본총계를 절반으로 깎았는데
**통과했다.** 막아야 하는데 통과했으니 구현이 틀린 것이다.

원인을 찾으니 DART는 같은 계정을 **연결재무제표(CFS)와 별도재무제표(OFS) 두 벌로** 보낸다.

```
자산총계: 2행
   fs_div=CFS (연결재무제표)  160,146,430,758,072
   fs_div=OFS (재무제표)      122,135,032,514,289
```

**38조 원 차이다.** 그런데

- `check_financial_quality` 는 `{indicator_id: amount}` 로 접었다 → 마지막 행이 이긴다
- `load_financials` 의 PK 는 `(corp_code, bsns_year, report_code, indicator_id)` 다.
  `fs_div` 가 없다 → `ON CONFLICT DO UPDATE` 가 마지막 행으로 덮어쓴다

전 보존 응답을 셌다.

| | |
|---|---|
| CFS·OFS를 함께 반환한 보고서 | **56 / 56 (전부)** |
| 마지막-승자 규칙이 고른 기준 | **238 / 238 전부 OFS(별도)** |

창고 전체와 서빙 50행이 **별도재무제표**였다. 아무도 그렇게 정하지 않았고, 어디에도
기록되지 않았고, 문서에도 없었다. 응답 순서가 데이터의 의미를 정하고 있었다.

**항등식이 50/50 성립했던 것도 옳아서가 아니었다.** 두 기준이 각자 균형을 이루므로
어느 쪽이 이겼든 그 안에서는 맞았다. 검증이 통과했다는 사실이 검증이 옳다는 뜻은 아니다.

### 처리

보험그룹 비교의 표준은 연결이므로 **연결(CFS)을 계약 기준으로 선언**했다.

- `resolve_indicators(..., basis=CONSOLIDATED)` 가 선언된 기준만 채택한다
- 선언한 기준이 없으면 **다른 기준으로 조용히 대체하지 않는다.** 품질 계약이
  `NO_INDICATORS` 또는 `MISSING_INDICATOR` 로 막는다
- 다른 기준의 행은 버리지 않고 `OTHER_BASIS` 로 기록한다 (869건)
- `bronze_financial_indicator` 에 `fs_div` 컬럼을 추가해 **각 값이 어느 기준에서
  왔는지 행에 남긴다**

## 4. 검증 — 양쪽 다 쟀다

**거짓 양성 없음.** 실데이터 전체 파이프라인 재실행에서 재무 품질 차단 **0건**.
50개 회사-분기를 하나도 막지 않았다.

**거짓 음성 없음.** 실제 보존된 DART 원본에 오염을 주입했다.

| 오염 | 결과 |
|---|---|
| 원본 그대로 | 통과 |
| 연결 자본총계 절반 | **차단** `BALANCE_SHEET_BROKEN` |
| 자산총계 부호 반전 | **차단** `NEGATIVE_STOCK` |
| 자산총계 행 삭제 | **차단** `MISSING_INDICATOR` |
| 빈 응답 | **차단** `NO_INDICATORS` |
| 직전분기 대비 3배 | **차단** `ASSET_JUMP_EXCEEDED` |
| 직전분기 대비 +8% | 통과 (실측 최대가 +8.73%다) |
| 연결 행 전부 제거 | **차단** `NO_INDICATORS` — 별도로 대체하지 않는다 |
| 별도 자본총계 절반 | 통과 — 계약 기준이 연결이므로 의도된 동작 |

## 5. 리뷰어의 재무 대응

금리는 값 하나를 원본과 대조하면 된다. 재무의 위반은 항등식·부호·결측이라 단일 값
비교로 답이 나오지 않는다.

`financial_provenance` 는 **보존된 원본을 다시 해석하고 같은 계약을 다시 적용한다.**
질문은 동일하다 — 이 위반이 출처의 것인가, 우리가 만든 것인가.

- 재현된다 → `CONTEXT`. 출처가 그렇게 보냈다
- 재현되지 않는다 → `SUPPORTS_DEFECT`. 원본은 정합한데 우리 쪽만 깨졌다. 버그다

`financial_precedent` 는 금리 테이블 대신 재무 테이블을 본다. 금리용 probe 를 그대로
쓰면 전례가 언제나 "없음"으로 나온다. 근거가 없는 것처럼 보이지만 실제로는 잘못된 곳을
보고 있는 것이고, 둘은 구분되어야 한다.

`blast_radius` 도 소스를 구분한다. 재무는 서빙 뷰의 구동 테이블이라 막으면 그 회사 행
자체가 사라지고, 금리는 `LEFT JOIN` 이라 행은 남고 열이 빈다. 반려의 비용이 다르다.

연동 계열 대조는 재무에 적용되지 않는다. 없는 근거를 만들지 않고 적용 불가임을 명시한다.

## 6. 남는 한계

- 계약 기준을 연결로 **선언**했다. 별도 기준 분석이 필요하면 계약을 바꿔야 하며,
  두 기준을 동시에 서빙하지 않는다.
- 급변 임계 25%는 10분기 관측에서 유도했다. 표본이 늘면 다시 재야 한다.
- 회계 항등식은 정확 비교한다. 실측 상대오차가 0이었기 때문이며, 다른 원천에서는
  반올림 오차가 있을 수 있다.
