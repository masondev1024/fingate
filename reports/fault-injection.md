# Fault Injection 실험 결과

- 실행일: 2026-09-07
- 대상 시계열: `base_rate_daily` (한국은행 기준금리), 실데이터 36행
- 원자료: `reports/fault-injection.json`

## 사전 등록

오염 카탈로그 9종은 설계 문서(커밋 `88a07c9`, 10:48)에 **게이트 구현 전** 고정했다.
게이트는 그 이후(10:55~11:54)에 만들었다. 결과를 보고 카탈로그를 조정하지 않았다.

2종(`dart_throttled`, `series_swapped`)은 개발 중 발견한 **사후 추가**이며 구분해 표기한다.

목표 차단율은 사전에 선언하지 않았다. 목표를 정하면 그 숫자를 맞추도록 게이트를 조정하게 된다.

## 비교 대상

- **대조군(naive)**: HTTP 상태만 확인하고 파싱해 그대로 서빙. 실제로 흔히 쓰이는 방식이다.
  두 API가 오류에도 HTTP 200을 주므로 오류 페이로드가 데이터로 적재된다.
- **실험군(gated)**: 응답·스키마·품질 3계층 계약과 승인 게이트를 거친다.

"서빙 도달"은 오염된 값이 소비자에게 **최신 값으로 노출**되는 것이다.
degraded로 직전 정상 스냅샷을 내보내는 것은 도달이 아니다.

### 요약

| 지표 | 값 |
|---|---|
| 전체 11종 서빙 도달률 | 대조군 **90.9%** → 실험군 **0.0%** |
| 사전 등록 9종만 | 대조군 **88.9%** → 실험군 **0.0%** |
| 대조군 실패 유형 | 조용한 오염 10건, 크래시 1건 |
| 차단 계층 분포 | response 4, schema 4, quality 3 |
| 정상 데이터 대조 | 서빙 도달 **유지** (거짓 양성 0) |

## 해석 경계

- **조용한 오염과 크래시는 다르다.** zip 케이스에서 대조군은 서빙하지 않고 크래시했다.
  크래시는 최소한 눈에 띈다. 나머지 10건은 아무 신호 없이 오염된 값을 서빙했다.
  이쪽이 훨씬 위험하다.
- 차단율 0%는 **이 11종에 대한** 결과다. 카탈로그에 없는 오염 유형은 측정하지 않았다.
- 오염 4종은 실제 API가 반환하는 것을 관측했고(`INFO-100`, `INFO-200`, `NOT_ZIP`, `101`),
  나머지 7종은 정상 데이터에 인위적으로 주입했다. 후자는 **실제 사고 사례가 아니다.**
- 이것은 실험 결과이지 **운영 실적이 아니다.** 실제 트래픽에서 측정한 값이 아니다.
- 정상 데이터가 계속 서빙된다는 점을 함께 확인했다. 모두 막는 게이트는 차단율 100%지만
  쓸모가 없다.
